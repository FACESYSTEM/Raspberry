# 個室カメラ（ESP32）仕様書

状態: **仕様の確認中（まだ作っていない）**。この内容で合意できたら、Pi 側 → ESP32 側の順に作る。

## 目的

個室の**入口**で、入ってくるグループの顔と服装を撮り、サーバでグループの突き合わせに使う。
撮る・送るまでを端末でやり、顔の検出、照合、ベストショットの選択、グループの判定はすべて
サーバが**後で**処理する（リアルタイムの判断は要らない）。

## 全体の形

```
 個室1 入口 [ESP32 カメラ＋人感センサー] ─┐
 個室2 入口 [ESP32 カメラ＋人感センサー] ─┼─ 店の Wi-Fi ─→ [Pi 5（バックヤード・店に 1 台）] ─→ サーバ
   …                                      ┘                 部屋ごとに別の端末として送る
```

- ESP32 と Pi 5 は**同じ Wi-Fi（同じネットワーク）**につなぐ。店内で完結し、インターネットに出るのは Pi 5 からサーバへの送信だけ。
- Pi 5 は店に 1 台。個室 5〜10 部屋をまとめて受け持つ。
- サーバから見ると、個室ごとに 1 台の端末（今の Pi の撮影端末と同じ扱い）。

## 機材（1 部屋分）

| 物 | 型番・例 | 備考 |
|---|---|---|
| 本体 | Seeed Studio XIAO ESP32S3 Sense | Wi-Fi（2.4GHz）・カメラ・microSD の差込口付き。技適の表示を確認する |
| カメラ | OV5640（XIAO 用・ヒートシンク付き） | 500 万画素・ピント自動。付属の OV2640 と写りを比べて決める |
| 人感センサー | AM312（焦電型） | 白い丸いレンズは外に出す（ガラス・アクリル越しだと反応しない） |
| 記録 | microSD 64GB（FAT32 に直して使う） | 撮影中のコマを貯める |
| 電源 | USB 充電器（5V・1A 以上）＋ USB-C | **コンセントから給電**（電池運用はしない） |
| 配線 | ジャンパーワイヤー、はんだ付け | 人感センサー ↔ 本体の 3 本（3.3V・GND・信号） |

## ESP32 の動き

```
 待機: カメラは止める。人感センサーだけが見張る。Wi-Fi はつないだまま待つ
   │ 人感センサーが反応した、かつ「撮ってよい」（Pi 5 に聞いた結果）
   ▼
 撮影: カメラを起こして撮る。コマは送らずに microSD に貯める
   │ センサーの反応がなくなって 30 秒、または撮り始めて 2 分
   ▼
 送信: 貯めたコマを Pi 5 へまとめて送る。受け取りを確かめたら microSD から消す
   ▼
 待機に戻る
```

| 項目 | 値（仮・後から変えられる） |
|---|---|
| 1 回の撮影の長さ | 最大 2 分 |
| 早めに終える | センサーの反応がなくなって 30 秒 |
| 撮る大きさ | 640×480〜800×600 前後（写りと温度を見て決める） |
| 毎秒の枚数 | 15 枚前後を上限（実物で測って決める） |
| 生存確認 | 5 分に 1 枚、静止画を Pi 5 に送る（管理画面の生存確認用） |
| 撮ってよいか | Pi 5 に聞く（店に割り当て済み、管理画面の撮影スイッチが「する」、撮影窓の中） |
| 時刻 | Pi 5 の返事に入っている時刻で合わせる。取れなければインターネットの時刻（NTP） |

- 時刻が合っていないうちは撮らない（後から送るので、撮った時刻が正しくないとサーバで突き合わせられない）。
- 送れなかったコマは microSD に残り、つながったら続きから送る。
- microSD の空きが少なくなったら、古い撮影から消す（消した数は記録する）。
- Wi-Fi に長くつながらないときは、撮影中でなければ自分で再起動する。

### ESP32 の設定（microSD の `fscam.txt`）

Mac で書き換えられるように、microSD のファイルに書く。

```
ssid=店のWi-Fi名
password=パスワード
hub=fs-pi-test.local      # Pi 5 の名前（または IP アドレス）
cam=room1                 # 部屋の名前（Pi 5 側の部屋名と同じにする）
key=合言葉                 # Pi 5 との合言葉（よその機器から送られないように）
```

### 配線

| 人感センサー（AM312） | XIAO |
|---|---|
| VCC | 3V3 |
| GND | GND |
| OUT | D0 |

### 書き込み

Mac に Arduino IDE（無料）を入れ、USB-C ケーブルで書き込む。手順は日本語で別にまとめる。

## Pi 5 側

### 受け口（`fservice-hub`）

店内の ESP32 からの受け取り口。Pi 5 で常に動かす。

| 口 | 中身 |
|---|---|
| `POST /v1/clip?cam=<部屋>` | 1 回の撮影分のコマ。受け取ったら部屋ごとの受け取り箱に入れる |
| `POST /v1/still?cam=<部屋>` | 5 分ごとの静止画（生存確認・画角確認用） |
| `GET /v1/state?cam=<部屋>` | 「撮ってよいか」と今の時刻を返す |

- どの返事にも Pi 5 の時刻を入れる（ESP32 の時刻合わせ用）。
- 合言葉（`key`）が合わない、知らない部屋名のものは受け取らない。
- 受け取り箱があふれそう、ディスクの空きが少ない、ときは「後で送って」と返す（ESP32 は microSD に残して後で送り直す）。
- 同じコマが 2 回届いても、二重には数えない。

### 撮影の形式（ESP32 → Pi 5）

1 回の撮影分を 1 つのファイルにして、そのまま送る。コマごとに

```
"FSF1"（4 バイト） ＋ 撮った時刻（UNIX ミリ秒・8 バイト） ＋ JPEG の長さ（4 バイト） ＋ JPEG
```

を並べたもの。ESP32 は撮りながらこの形で microSD に書き、送るときはファイルをそのまま流す。

### 部屋ごとの端末

- 部屋ごとに今の撮影プログラムを 1 つずつ動かす（`fservice-room@<部屋>`）。カメラの代わりに受け取り箱からコマを読む。
- 動きのないコマを削る、まとめて送る、回線が切れたら貯める、店への割り当て、心拍、生存確認、などは今の Pi の撮影端末と同じ仕組みをそのまま使う。
- 端末の名前は `pi-<Pi 5 の名前>-<部屋>`（例: `pi-d0d9930dcdbf-room1`）。管理画面の「未割当の端末」に部屋ごとに出るので、それぞれ店に割り当てる。
- 撮影窓の外に遅れて届いたコマも捨てずに送る（撮影窓は ESP32 が撮り始めるときに守っている）。

### 部屋の追加

```
sudo ./deploy/add-room.sh room1
```

で部屋を 1 つ足す（設定ファイルを作り、部屋の端末を動かす）。

### 店の Wi-Fi の形

| 店の状況 | 形 |
|---|---|
| ふつう | ESP32 も Pi 5 も**店のスタッフ用 Wi-Fi**につなぐ。Pi 5 はできれば LAN ケーブル |
| 店の Wi-Fi が使えない・不安定 | Pi 5 がカメラ専用の Wi-Fi を出し、Pi 5 は LAN ケーブルでネットへ |

お客様用のフリー Wi-Fi は、機器どうしが通信できない設定のことが多いので使わない。

## 決めたこと

- 長く撮り続けない。動きから 2 分でベストショットが撮れればよい（突き合わせは入口の服と顔でサーバが判断）。
- 人感センサーを標準で付ける（熱が減る・照明やカーテンで誤反応しない）。
- 電源はコンセント。
- 撮影中は送らず、終わってからまとめて送る。
- ESP32 から直接サーバへは送らず、Pi 5 を経由する（ESP32 は撮って流すだけにして、壊れにくくする）。

## 届いてから確かめること

1. 付属カメラ（OV2640 か OV3660 か）と OV5640 の写り・ピント・暗い所での写り
2. 毎秒の枚数（撮る大きさごと）
3. 待機中と撮影中の温度（ヒートシンクの効き）
4. 人感センサーが反応してから撮り始めるまでの遅れ
5. 「人が来る → 撮る → Pi 5 → サーバ」が通ること、Wi-Fi を切っても後で送られること

## 気をつけること

- カメラは**入口だけ**が写る向きにする。部屋の中の座っている人が写ると、そのたびに撮り直しが始まる。
- 人感センサーはエアコンの吹き出し口・暖房・直射日光を避ける。
- 撮影していることの掲示は、顔の照合に使っていることが分かる文面にする（今 Pixel で顔の照合をしている店と同じ文面）。
