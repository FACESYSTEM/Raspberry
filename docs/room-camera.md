# 個室カメラ（ESP32）仕様書

状態: **Pi 側（`fservice_pi/hub.py`・`rooms.py`、`deploy/add-room.sh`）と ESP32 側（`esp32cam/fscam/fscam.ino`）を作った。ESP32 側は実機での書き込み・確認がまだ。** 書き込み手順: `docs/room-camera-flash.md`

## 目的

個室の**入口**で、入ってくるグループの顔と服装を**数枚**撮り、サーバでグループの突き合わせに使う。
撮る・送るまでを端末でやり、顔の検出、照合、ベストショットの選択、グループの判定、
スタッフの除外はすべてサーバが**後で**処理する（リアルタイムの判断は要らない）。

動画のように撮り続けず、**人が来たときに数枚の写真を撮る**ことで、データ量・熱・費用を小さくし、
どの店にも同じ物を置ける単純な端末にする。

## 全体の形

```
 個室1 入口 [ESP32 カメラ＋人感センサー] ─┐
 個室2 入口 [ESP32 カメラ＋人感センサー] ─┼─ 店の Wi-Fi ─→ [Pi 5（バックヤード・店に 1 台）] ─→ サーバ
   …                                      ┘                 部屋ごとに別の端末として送る
```

- ESP32 と Pi 5 は**店のルーターの Wi-Fi（同じネットワーク）**につなぐ。店内で完結し、インターネットに出るのは Pi 5 からサーバへの送信だけ。
- Pi 5 は店に 1 台。個室 10〜20 部屋をまとめて受け持つ。
- サーバから見ると、個室ごとに 1 台の端末（今の Pi の撮影端末と同じ扱い）。
- 廊下や店の入口など、Pi 5 から 5〜10m 以内で全員が通る場所は、今の USB カメラも併用できる（写りが一番よい）。

## 機材（1 部屋分）

| 物 | 型番・例 | 備考 |
|---|---|---|
| 本体 | Seeed Studio XIAO ESP32S3 Sense | Wi-Fi（2.4GHz）・カメラ・microSD の差込口付き。外付けアンテナが付属。技適の表示を確認する |
| カメラ | OV5640（XIAO 用・ヒートシンク付き） | 500 万画素・ピント自動。付属のカメラと写りを比べて決める |
| 人感センサー | AM312（焦電型） | 白い丸いレンズは外に出す（ガラス・アクリル越しだと反応しない） |
| 記録 | microSD 64GB（FAT32 に直して使う） | 撮った写真を送るまで貯める |
| 電源 | USB 充電器（5V・1A 以上）＋ USB-C | **コンセントから給電** |
| 配線 | ジャンパーワイヤー、はんだ付け | 人感センサー ↔ 本体の 3 本（3.3V・GND・信号） |

## ESP32 の動き

```
 待機: カメラは止める。人感センサーだけが見張る。Wi-Fi はつないだまま待つ
   │ 人感センサーが反応した、かつ「撮ってよい」（Pi 5 に聞いた結果）
   ▼
 撮影: カメラを起こして、数枚撮る（microSD に書く）
   │ 反応が続いていれば撮り続ける（上限あり）
   ▼
 送信: すぐ Pi 5 へ送る。受け取りを確かめたら microSD から消す（送れなければ残して後で）
   ▼
 待機に戻る
```

| 項目 | 値（仮・後から変えられる） |
|---|---|
| 1 回の反応で撮る枚数 | **毎秒 2〜3 枚 × 10 秒前後（20〜30 枚）** |
| 反応が続くとき | 反応が続く間は撮り続ける。1 回の上限 60 秒 |
| 撮る大きさ | 1280×960 前後（写真なので動画より大きく撮る。写りと温度を見て決める） |
| 1 回のデータ量 | 1〜3MB 前後（動画で撮るときの数十分の一） |
| 生存確認 | 5 分に 1 枚、静止画を Pi 5 に送る（管理画面の生存確認・画角確認用） |
| 撮ってよいか | Pi 5 に聞く（店に割り当て済み、管理画面の撮影スイッチが「する」、撮影窓の中） |
| 時刻 | Pi 5 の返事に入っている時刻で合わせる。取れなければインターネットの時刻（NTP） |

- 撮影を時間で区切ったり、間引いたりはしない（スタッフ・トイレの出入りも撮って、サーバで除外する）。
- 時刻が合っていないうちは撮らない（後から送ることがあるので、撮った時刻が正しくないとサーバで突き合わせられない）。
- 送れなかった写真は microSD に残り、つながったら続きから送る。
- microSD の空きが少なくなったら、古い写真から消す（消した数は記録する）。

### ESP32 の設定（microSD の `fscam.txt`）

Mac で書き換えられるように、microSD のファイルに書く。

```
ssid=店のWi-Fi名
password=パスワード
hub=fs-pi-test.local      # Pi 5 の名前（または IP アドレス）
cam=room1                 # 部屋の名前（Pi 5 側の部屋名と同じにする）
key=合言葉                 # Pi 5 との合言葉（よその機器から送られないように）
```

|---|---|
| VCC | 3V3 |
| GND | GND |
| OUT | D0 |

## Pi 5 側

### 受け口（`fservice-hub`）

店内の ESP32 からの受け取り口。Pi 5 で常に動かす。

| 口 | 中身 |
|---|---|
| `POST /v1/clip?cam=<部屋>` | 1 回の撮影分の写真。受け取ったら部屋ごとの受け取り箱に入れる |
| `POST /v1/still?cam=<部屋>` | 5 分ごとの静止画と、カメラの状態（電波の強さ・温度・再起動の回数など） |
| `GET /v1/state?cam=<部屋>` | 「撮ってよいか」と今の時刻を返す |
| `GET /`（ブラウザで開く） | **部屋ごとの一覧**: 最後に連絡があった時刻、電波の強さ、温度、最後の写真。設置のときにスマホで見る |

- どの返事にも Pi 5 の時刻を入れる（ESP32 の時刻合わせ用）。
- 合言葉（`key`）が合わない、知らない部屋名のものは受け取らない。
- 受け取り箱があふれそう、ディスクの空きが少ない、ときは「後で送って」と返す（ESP32 は microSD に残して後で送り直す）。
- 同じ写真が 2 回届いても、二重には数えない。

### 撮影の形式（ESP32 → Pi 5）

1 回の撮影分を 1 つのファイルにして、そのまま送る。写真ごとに

```
"FSF1"（4 バイト） ＋ 撮った時刻（UNIX ミリ秒・8 バイト） ＋ JPEG の長さ（4 バイト） ＋ JPEG
```

を並べたもの。ESP32 は撮りながらこの形で microSD に書き、送るときはファイルをそのまま流す。

### 部屋ごとの端末

- 1 つのプログラム（`fservice-rooms`）の中で全部屋を受け持つ（20 部屋でもメモリが足りるように、部屋ごとに別のプログラムは立てない）。
- 店への割り当て、心拍、生存確認、まとめて送る、回線が切れたら貯める、などは今の Pi の撮影端末と同じ仕組みを使う。
- 動きのないコマを削る処理は**しない**（人感センサーが反応したときの数枚だけなので、全部送る）。
- カメラの状態（電波の強さ・温度など）は、部屋の端末の心拍に載せてサーバへ送る（管理画面で部屋ごとに見える）。
- 端末の名前は `pi-<Pi 5 の名前>-<部屋>`（例: `pi-d0d9930dcdbf-room1`）。管理画面の「未割当の端末」に部屋ごとに出るので、それぞれ店に割り当てる。
- 撮影窓の外に遅れて届いた写真も捨てずに送る（撮影窓は ESP32 が撮り始めるときに守っている）。

**サーバ側に確かめること:** 写真を 1280×960 前後で送ってよいか（今の撮影端末は長い辺 640 で送っている。
1 枚 200KB の上限には収める）。だめなら Pi 5 で長い辺 640 に縮めて送る。

### 部屋の追加

```
sudo ./deploy/add-room.sh room1
```

で部屋を 1 つ足す。

## 電波の届く範囲（一番の心配）

| 対策 | 内容 |
|---|---|
| 付属の外付けアンテナを使う | 基板に付いているアンテナより届きやすい。ケースの外か、金属から離した所に出す |
| 設置前に測る | ESP32 を電源につないで入口に置くと、Pi 5 の一覧（ブラウザ）に電波の強さが出る。弱い部屋は場所を変えるか中継機 |
| 置いた後も見張る | 電波の強さは 5 分ごとに Pi 5 とサーバに届く。弱くなった部屋が管理画面で分かる |
| 途切れても失わない | 写真は microSD に残るので、電波が戻れば後から送られる |
| 中継機 | 届かない部屋がまとまっている所に、店のルーターと同じメーカーの中継機（メッシュ）を足す |

目安: 電波の強さ（RSSI）が -70 より強ければ安定、-70〜-80 は送れるが遅い、-80 より弱いと途切れやすい。

## 止まらないための仕組み（想定される不具合と対策）

| 想定 | 気づき方 | ESP32 がすること | 人がすること |
|---|---|---|---|
| カメラが撮れない（起動しない・写真が来ない） | 撮影で失敗が続く | カメラを開き直す。3 回続けてだめなら再起動 | 一覧で「カメラ失敗」が増えていればケーブルを確認 |
| プログラムが固まる | 見張り役（ウォッチドッグ）が 30 秒反応なしを検知 | 自動で再起動 | なし |
| メモリが少しずつ減る（長く動かすと起きやすい） | 空きメモリを見張る | 少なくなったら、撮影していない時に再起動。**毎日、営業時間外に 1 回再起動** | なし |
| Wi-Fi が切れる | つながらない時間を数える | つなぎ直す。10 分つながらなければ再起動 | 長く続く部屋は電波を確認 |
| Pi 5 が見つからない（アドレスが変わった等） | 送信の失敗が続く | 名前（`.local`）で探し直す | Pi 5 のアドレスをルーターで固定 |
| microSD の不具合（抜けた・壊れた・いっぱい） | 書き込みの失敗 | 書けなければ写真をその場で直接送る。いっぱいなら古い写真から消す | 一覧で「SD 失敗」が出ていればカードを交換 |
| 書き込み中の停電 | 起動時にファイルを調べる | 壊れた写真ファイルは捨てて、読める分だけ送る | なし |
| 時刻が合わない | 時刻合わせの失敗 | 合うまで撮らない（時刻のずれた写真を作らない） | なし（つながれば合う） |
| 人感センサーが反応しっぱなし／全く反応しない | 反応の続く時間・回数を数える | 反応しっぱなしなら 60 秒で撮影を止め、次の反応まで休む | 一覧で「反応しっぱなし」「1 日反応なし」の部屋を確認 |
| 熱くなりすぎる | 本体の温度を測る | 一定の温度を超えたら撮影の間隔を空ける | ケースの通気を見直す |
| 電源が不安定（USB 充電器の力不足） | 電圧低下による再起動の回数 | 再起動の理由を記録して送る | 再起動が多い部屋は充電器を交換 |
| 起動を何度も繰り返す | 再起動の回数 | 短い時間に何度も再起動したら、撮影を止めて生存確認だけ続ける | 一覧で確認 |
| 部屋のカメラが止まったのに気づかない | Pi 5 が「5 分ごとの静止画」の途絶えを見る | — | 管理画面で「生存確認の写真が止まっている」と出る（今の端末と同じ） |

ESP32 は、再起動の回数と理由、カメラ・SD・Wi-Fi の失敗の回数、温度、電波の強さを 5 分ごとに Pi 5 へ送る。

## 出荷前の慣らし運転（初期不良を見つける）

事務所で、出荷する台数をまとめて **24〜48 時間**動かし続ける。

- 定期的に人感センサーの前を通る（または一定間隔で撮影させる試験の設定にする）
- Pi 5 の一覧で、全台の「再起動の回数」「失敗の回数」「温度」「電波」を確認する
- 1 台でも再起動や失敗が多いものは出荷しない

## 規模（1 店 10〜20 部屋）

| 心配 | 見込み |
|---|---|
| Pi 5 の処理 | 数枚ずつなので軽い。20 部屋が同時に撮っても余裕がある |
| Pi 5 のメモリ | 1 つのプログラムで全部屋を持つので足りる |
| 店内の Wi-Fi | 1 回の撮影で 1〜3MB。20 部屋でも普通のルーターで足りる |
| Wi-Fi のつなぎ先 | 店のルーター（Pi 5 が出す Wi-Fi は 10 台前後までなので、使うのは小さい店だけ） |

進め方: **1 部屋 → 3 部屋 → 全部屋** と段階的に増やし、各段階で電波・温度・不具合の回数を実物で確かめる。

## 決めたこと

- 動画のように撮り続けない。人感センサーの反応ごとに数枚の写真を撮る。
- スタッフ・トイレの出入りも撮り、サーバで除外する（時間で区切ったり、端末で間引いたりしない）。
- 人感センサーを標準で付ける（熱が減る・照明やカーテンで誤反応しない）。
- 電源はコンセント。Wi-Fi は店のルーター。
- ESP32 から直接サーバへは送らず、Pi 5 を経由する（ESP32 は撮って流すだけにして、壊れにくくする）。

## 届いてから確かめること

1. 付属カメラと OV5640 の写り・ピント・暗い所での写り（撮る大きさごと）
2. 人感センサーが反応してから 1 枚目を撮るまでの遅れ
3. 待機中と撮影中の温度（ヒートシンクの効き）
4. 「人が来る → 撮る → Pi 5 → サーバ」が通ること、Wi-Fi を切っても後で送られること
5. 外付けアンテナあり・なしでの電波の強さ

## 気をつけること

- カメラと人感センサーは**入口に向ける**。部屋の中の座っている人に反応すると、撮影が増える。
- 人感センサーはエアコンの吹き出し口・暖房・直射日光を避ける。
- 撮影していることの掲示は、顔の照合に使っていることが分かる文面にする（今 Pixel で顔の照合をしている店と同じ文面）。
