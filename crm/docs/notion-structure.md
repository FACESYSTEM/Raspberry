## 2. CRM でのデータの分け方

**決まったものは `CONVENTIONS.md` §7（言葉）と `app/models.py`（表）が正。**
ここには Notion の列がどこへ行くかだけを書く。

```
corps 1 ─── * guests * ─── * casts      （assignments: 担当レベル・付記）
                 │
                 ├── * bottles          （キープボトル 1 本 = 1 行）
                 └── * visits           （来店 1 回 = 1 行）
```

| Notion の列 | 行き先 | 取り込みのルール |
|---|---|---|
| No.付_個人ゲスト名（自動） | 持たない | 番号と名前から毎回作る。番号・名前が空のときだけ、ここから拾う |
| Guest_No. | `guests.guest_no` | `Gu_` を外して数字だけ。空・重複はそのまま入れて要確認に出す |
| 個人ゲスト名 / 個人フリガナ | `guests.name` / `kana` | |
| 法人・団体名 / フリガナ | `corps.name` / `kana` | 名前が完全に同じなら1社。`㈱`／`株式会社` は寄せない（人が決める） |
| 役職 | `guests.title` | **担当キャスト名と同じなら入れない**（列ずれ）。備考の `役職:` を使う |
| ネック名 | `guests.neck_name` | |
| ボトル | `bottles`（1本1行） | 分けられた分だけ行にする。`label` に元の書き方を残す。分けられない行は一覧に出す |
| 担当キャスト | `casts` / `assignments` | `CA_25_〇〇（A）` → 番号25・名前〇〇・付記A。`no-data` は担当を作らない（＝分からない） |
| 担当レベル | `assignments.level` | そのまま。`メインA2` は人に聞く |
| 誕生日 | `guests.birth_month` / `birth_day` | **年は入れない**（全件2026＝分からない） |
| 備考 | `guests.note` ほか | `登録日:` → `registered_on`、`役職:` → `title`。備考そのものは残す |
| 来店日 | `visits` 1件 | |
| 来店記録 | 後回し | 4件だけ。リンク先の DB を見てから |
| 電話・メール・住所 | `guests.tel` / `email` / `address` | 0件 |

## 3. 取り込みで気をつけること

- **Guest_No. が CRM の顧客番号**になる。重複・欠番・`Gu_` の有無を取り込み前に一覧にする
- タイトルの「（自動）」は Notion の自動化で作っているらしいが、古い行は手書き。CRM では guest_no と name から表示名を毎回作る（保存しない）
- `no-data` は「担当なし」として扱い、文字としては残さない
- 元の文字列（ボトル・担当キャスト・備考）は取り込み後も参照できるようにしておく
- ゲストの個人情報なので、取り出したデータ（CSV・JSON）はリポジトリに入れない（`.gitignore` 済み）
