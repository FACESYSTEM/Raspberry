# 開発規約

**着手前に読むこと。**AIエージェントに実装させる場合は、このファイルを
`CLAUDE.md` としても置く（同じ内容を読ませる）。

---

## 1. 最優先の3つ

1. **担当するフォルダの外を触らない。**共有ファイル（`models.py` / `base.html` /
   `static/app.css` / ルート規約）はオーナーを決め、合意なしに変えない
2. **§3〜§5 の契約を破らない。**URL・API応答形・権限デコレータは全員共通の外部仕様
3. **用語は §7 の辞書に統一する。**ゆらぎを許すと検索が効かなくなる

## 2. 技術（固定）

Python 3.11+／Flask／SQLAlchemy／Flask-Login／Flask-WTF(CSRF)／Jinja2／
SQLite／Gunicorn／pytest。

- **生SQLを書かない。**ORM経由に統一する
- **外部CSSフレームワークを使わない。**`static/app.css` に集約する
- **フロントは素のJS＋`fetch`。**ビルド工程を持たない

## 3. URL・ルート

- 画面は `/<もの>` と `/<もの>/<id>`
- 部分更新は `PATCH /api/<もの>/<id>`
- 一覧のクエリは**全画面共通**：`?q=&sort=&dir=asc|desc&page=`
- 並び替えは**ホワイトリスト**。範囲外は無視する（エラーにしない）
- Blueprint名＝フォルダ名。エンドポイントは `<bp>.<動作>`

## 4. API応答形

```
成功  200 {"ok": true, "value": ..., "history_id": ...}
入力  400 {"ok": false, "error": "validation", "message": "日本語"}
権限  403 {"ok": false, "error": "forbidden", "message": "..."}
無い  404 {"ok": false, "error": "not_found", "message": "..."}
```

## 5. 権限

- 画面・APIには `@login_required`。役割制限は `@role_required(...)`
- **取得は必ず `scope_query` を通す。**全件クエリを画面に出さない。
  いま全役割で全件でも、呼び出し口だけ通しておけば後から絞り込みを足せる
- パスワードはハッシュのみ。**平文保存・ログ出力を禁止する**

## 6. 更新と履歴

- インライン編集は**許可フィールドのホワイトリスト**内のみ
- **必ず `ChangeHistory.record()` を通してから保存する。**履歴を伴わない
  直接UPDATEを書かない
- **秘密の値は履歴に入れない**（「変更しました」とだけ書く）
- 消さずに `archived_at` で下げる。履歴と集計に要る

## 7. 用語辞書（**業務の言葉で固定する**）

日本語とコード識別子を1対1で固定する。**ゆらぎを許すと検索が効かなくなる。**

元にしたのは、店が使っている Notion「顧客管理（シンプル構成）」の列名と、
その書き出し（2,098行）に実際に入っていた値。**店に無い言葉を持ち込まない。**
来てくださる方を指す言葉は Notion の列名どおり「**ゲスト**」ひとつ
（`個人ゲスト名`・`Guest_No.`・`Gu_` の番号）。

### 土台

| 日本語 | コード名 | 補足 |
|---|---|---|
| 利用者 | `user` | このシステムにログインする人。役割は `role`（§7.5） |
| 変更履歴 | `change_history` | |
| 対応履歴 | `comment` | ゲストごとのメモ・申し送り |

### 業務

| 日本語 | コード名 | 補足 |
|---|---|---|
| ゲスト | `guest` | **来てくださる方を指す語。これ1つで呼ぶ** |
| ゲスト番号 | `guest_no` | Notion の `Guest_No.`。画面では `Gu_1592` と出す。**未採番・重複が実在する**（§7.1） |
| フリガナ | `kana` | |
| 法人・団体 | `corp` | ゲストの勤め先・所属。**1つの法人に複数のゲスト** |
| 役職 | `title` | 法人・団体での役職 |
| ネック名 | `neck_name` | ボトルのネック札に書く呼び名 |
| 誕生日 | `birth_month` / `birth_day` / `birth_year` | **ゲストに聞いて入れる。**年は空でよい（§7.2） |
| キャスト | `cast` | 店のキャスト。Notion の `CA_25_〇〇` の 25 が `cast_no` |

### 7.1 ゲスト番号（`guest_no`）— 一意にしない

実データで、**空が2件・同じ番号が2件（2081）**あった。一意制約を付けると取り込めない。
番号の重複・未採番は「要確認」に出して、人が直す。

書き方は `Gu_1592`（2,075件）と `2695`（21件）が混在していた。
**持つのは数字だけ**にして、`Gu_` は画面で付ける。Notion のタイトル
（`【Gu_1592】〇〇` の形）は**持たない**。番号と名前から毎回作る（§7.6）。

### 7.2 誕生日 — 聞いて入れる。今日・今月を見落とさない

Notion の誕生日は76件すべて**年が2026**だった。年が分からないまま今年で入れている。
これを年として持つと、年齢が全員0歳になる。

```
birth_month / birth_day   ゲストに聞いて入れる。聞けていなければ空＝「未記録」
birth_year                聞けたときだけ。今年の年で埋めない。年齢は年があるときだけ出す
```

- 入れるのは**ゲストの画面の「誕生日」**から。月・日・年を**まとめて1回で保存する**
  （1項目ずつだと、4月30日→5月31日の直しが途中の「4月31日」で断られる）
- **今日が誕生日**（`is_birthday`）と**今月が誕生月**（`is_birth_month`）は年を見ずに判定する。
  ダッシュボードの一番上・一覧の印・一覧の絞り込みに出す
- 2月29日生まれは、うるう年でない年は2月28日に知らせる
- 「誕生日が未記録」でも絞り込める（**聞きに行く相手を探す**ため）。要確認には出さない
  （2,000件近くが未記録なので、要確認に出すと他の警告が埋もれる）

### 7.3 担当（`assignment`）— 「担当なし」と「不明」を分ける

Notion の担当キャストは **975件が `no-data`**（記録が無い）。
これを「担当なし」と読むと、担当がいるのに記録が無いゲストを見落とす。

| 状態 | 持ち方 | 画面 |
|---|---|---|
| 担当がいる | `assignment` が1行以上（`ended_at` が空） | キャスト名 |
| 担当なし（確かめた） | `guest.no_cast = True` | 「担当なし」 |
| 不明 | どちらでもない | 「不明」＋要確認（担当が不明） |

担当レベルの値の意味（`完全` と `メイン` の違い、`A1`/`A2`）は**まだ聞けていない。**
意味を推測して名前を付け替えない。Notion にある値をそのまま選択肢にする。

### 7.4 来店（`visit`）

Notion の `来店日` は1行に1つ（164件）。最終来店日か初回来店日かは**未確認。**
取り込みでは1回分の来店として入れ、**最終来店日・来店回数は来店から導く**（列で持たない）。
来店が1件も無いときは**「記録なし」**と出す（「来ていない」ではない）。

### 7.4.1 空のときの書き方

| 書き方 | 使うところ |
|---|---|
| 未記録 | 聞けば分かるもの（誕生日・電話・役職など） |
| 不明 | 担当キャスト（`no-data`）・登録日 |
| 記録なし | 来店 |
| 担当なし | 担当がいないと確かめたとき |

### 7.5 利用者の役割（`role`）

| 日本語 | コード名 | だれ |
|---|---|---|
| マスター | `master` | 開発側（当社）。作りかけの機能も見える |
| 管理者 | `owner` | 店の管理者。利用者の招待・選択肢・キャストの管理 |
| スタッフ | `staff` | 店のスタッフ。ゲスト・ボトル・来店・担当を見て直す |

**「担当者」を役割の名前に使わない。**この店で「担当」はキャストのこと（§7.3）。
**キャスト本人はログインしない**（店の回答）。勤怠管理を付けることになったら、
役割を足して §5 の `scope_query` で自分の分だけに絞る。

### 7.6 列で持たず導くもの

| 出すもの | 導き方 |
|---|---|
| 画面の名前 `Gu_1592 〇〇` | `guest_no` と `name` |
| 最終来店日・来店回数 | `visit` |
| いまの担当 | `assignment`（`ended_at` が空のもの） |
| 年齢 | `birth_year` があるときだけ |
| キャストの担当ゲスト数 | `assignment` |

### 7.7 使わない言葉

| 使わない | 理由 |
|---|---|
| 顧客 / customer / お客様 | 店の台帳の言葉は「ゲスト」 |
| 取引先 / partner | ひな形の見本の語 |
| 担当者（利用者の役割として） | 「担当」はキャストのこと。利用者は「スタッフ」 |
| 会社 / company | ゲストの勤め先は「法人・団体」（`corp`）。`company` は土台の自社の情報で使っている |
| ステータス（単独） | 何の状態かが分からず、全件同じ値のまま死ぬ（§8.5） |

## 8. コード

- **black**整形＋PEP8。型ヒントを付ける
- 公開関数に短い docstring（日本語可）。**なぜそうしたかを書く**
- 例外を握りつぶさない。想定内は §4 の形に、想定外はログして500
- ログに**個人情報・パスワード・トークン・業務データを出さない**

## 8.5 死ぬ列を作らない

台帳の `ステータス` は13件すべて「進行中」、`次回アクション` はほぼ「次回MTG」だった。
アポイント管理表の `進捗` `契約状況` は**一度も使われていない**。

**既定値のまま置いても困らない列は、必ず死ぬ。**

- 選択肢に**既定値を置かない**（未選択は未選択として出す）
- 埋まっていないことを**「要確認」として一覧に出す**（土台 §4.1）
- 埋めないと次に進めない場面を作る。**画面から促す**

## 9. テスト

- 機能ごとに1ファイル。**「動くか」ではなく「壊れたら困ることが守られているか」**
- 実データで踏んだ不具合は**必ず回帰テストにする**
- マージ前に全部通っていること

## 10. バッチ

- **`--dry-run` を既定にし、`--apply` で初めて書き込む。**件数と例を出す
- 人が入れた値を**上書きしない**（空いているところだけ埋める）
- メモ欄は**追記**する

## 11. 外部API

- **User-Agent を名乗る。**名乗らないと言語標準のUAになり、WAFに弾かれることがある
- 流量制限は**クライアント層で守る。**呼ぶ側に任せない
- ページングは**打ち切りの上限**を持つ
- 外部から叩かれるAPIは**CSRFの対象外にする**（`app/__init__.py` にコメントあり）。
  外し忘れると外部連携が黙って止まる

## 11.5 時刻

- **保存はUTC（タイムゾーン無し）、画面はJST。**`app/timeutil.py` を通す
- `datetime.utcnow()` を書かない（Python 3.12で非推奨・将来削除）。`utcnow()` を使う
- テンプレートで `strftime` を直接呼ばない。**`{{ 値|jst }}`** を使う
- 未設定の日時は「—」を出す。空欄にしない

## 12. 画面

- 数字は右揃え・桁区切り
- 合計だけでなく**内訳を出す**
- 空欄に「—」とだけ出さず、**なぜ出ないのかを書く**
- 押した瞬間に保存されるのか、ボタンが要るのかを**明示する**

## 13. 禁止

- 共有ファイル・ルート規約・API応答形を独断で変える
- 生SQL・DBの手編集
- 履歴を残さない更新／ホワイトリスト外の項目の更新
- 秘密のハードコード・ログ出力
- 汚れたデータ（未採番・未紐付け・重複）の無断削除
