# 開発規約

**着手前に読むこと。**AIエージェントに実装させる場合は、このファイルを
`CLAUDE.md` としても置く（同じ内容を読ませる）。

---

## 1. 最優先の3つ

1. **担当するフォルダの外を触らない。**共有ファイル（`models.py` / `base.html` /
   `static/app.css` / ルート規約）はオーナーを決め、合意なしに変えない
2. **§3〜§5 の契約を破らない。**URL・API応答形・権限デコレータは全員共通の外部仕様
3. **用語は §7 の辞書に統一する。**ゆらぎを許すと検索が効かなくなる

## 2. 技術（固定）

Python 3.11+／Flask／SQLAlchemy／Flask-Login／Flask-WTF(CSRF)／Jinja2／
SQLite／Gunicorn／pytest。

- **生SQLを書かない。**ORM経由に統一する
- **外部CSSフレームワークを使わない。**`static/app.css` に集約する
- **フロントは素のJS＋`fetch`。**ビルド工程を持たない

## 3. URL・ルート

- 画面は `/<もの>` と `/<もの>/<id>`
- 部分更新は `PATCH /api/<もの>/<id>`
- 一覧のクエリは**全画面共通**：`?q=&sort=&dir=asc|desc&page=`
- 並び替えは**ホワイトリスト**。範囲外は無視する（エラーにしない）
- Blueprint名＝フォルダ名。エンドポイントは `<bp>.<動作>`

## 4. API応答形

```
成功  200 {"ok": true, "value": ..., "history_id": ...}
入力  400 {"ok": false, "error": "validation", "message": "日本語"}
権限  403 {"ok": false, "error": "forbidden", "message": "..."}
無い  404 {"ok": false, "error": "not_found", "message": "..."}
```

## 5. 権限

- 画面・APIには `@login_required`。役割制限は `@role_required(...)`
- **取得は必ず `scope_query` を通す。**全件クエリを画面に出さない。
  いま全役割で全件でも、呼び出し口だけ通しておけば後から絞り込みを足せる
- パスワードはハッシュのみ。**平文保存・ログ出力を禁止する**

## 6. 更新と履歴

- インライン編集は**許可フィールドのホワイトリスト**内のみ
- **必ず `ChangeHistory.record()` を通してから保存する。**履歴を伴わない
  直接UPDATEを書かない
- **秘密の値は履歴に入れない**（「変更しました」とだけ書く）
- 消さずに `archived_at` で下げる。履歴と集計に要る

## 7. 用語辞書（**業務の言葉で固定する**）

日本語とコード識別子を1対1で固定する。**ゆらぎを許すと検索が効かなくなる。**

ヒアリング①の回答に基づく。**社内に無い言葉を持ち込まない。**
お客様全体を指す言葉は「顧問先」ひとつで、継続／スポット／OEM／紹介者の
呼び分けは社内に存在しない（Q3の回答が全て空欄）。

### 土台

| 日本語 | コード名 | 補足 |
|---|---|---|
| 利用者 | `user` | 役割は `role` |
| 変更履歴 | `change_history` | |
| 対応履歴 | `comment` | |

### 業務

| 日本語 | コード名 | 補足 |
|---|---|---|
| 顧問先 | `client` | **お客様全体を指す語。**これ1つで呼ぶ |
| 関係 | `relation` | 顧問先が持つ役割。**複数持てる**（§7.1） |
| 契約 | `contract` | 1顧問先に複数ありうる |
| 接触 | `touch` | 最終接触日の元。何を数えるかは §7.2 |
| 主担当 | `owner_name` | 〈担当A〉・〈担当B〉など |
| 顧問種別 | `service_kind` | 経営顧問／FC／社保・法人税削減スキーム 等 |
| 契約形態 | `contract_form` | 経営顧問／業務委託 |
| 月額顧問料 | `monthly_fee` | |
| 計上法人 | `company` | **㈱／合同の2法人**（§7.3） |
| 要確認 | `issues` | 消さずに一覧へ出す |

### 7.1 関係（`relation`）— 単一の列にしない

**1つの顧問先が複数の関係を同時に持つ。**実データで確認済み。

| 日本語 | コード名 | 実例 |
|---|---|---|
| 顧問先 | `advisory` | 継続の顧問契約 |
| OEM加盟 | `oem` | 人事診断のOEM加盟企業 |
| FC | `fc` | 台帳の顧問種別に実在 |
| 借入先 | `lender` | 資金調達管理シートに実在 |
| 貸付先 | `borrower` | 同上 |
| 紹介者 | `referrer` | アポイント管理表の紹介者 |
| 見込み | `prospect` | 商談中でまだ契約前 |

例：`株式会社労務ニュース` は 顧問先(FC) かつ OEM加盟 かつ 借入先。

**区分カラムを1本にしてはいけない。**入れると必ず取りこぼす。

### 7.2 接触（`touch`）— 何を数えるか

「連絡が止まっている先はどこか」を出すための基礎。
**数える対象を関数名とdocstringに明記する**（土台 §5「集計の分母を取り違えた」）。

```
数える    商談・アポ・定例MTG・ヒアリング（人が会話した記録）
数えない  請求書の送付・書類の格納・こちらから一方的に送っただけのもの
```

**迷ったら数えない。**「接触した」と誤って判定されると、放置に気づけなくなる。
数えないほうに倒せば、最悪でも「余分に警告が出る」で済む。

### 7.3 計上法人（`company`）

請求書の保管フォルダが2つに分かれている。**最初から両方を持つ。**

| 日本語 | コード名 |
|---|---|
| 〈社名〉 | `kk` |
| 〈別法人〉 | `gk` |

### 7.4 使わない言葉

| 使わない | 理由 |
|---|---|
| 取引先 / partner | ひな形の見本の語。業務で使っていない |
| 顧客 / customer | 社内で使われているのは「顧問先」 |
| ステータス（単独） | 台帳で全件「進行中」になり死んだ列。§8 の規則を参照 |

## 8. コード

- **black**整形＋PEP8。型ヒントを付ける
- 公開関数に短い docstring（日本語可）。**なぜそうしたかを書く**
- 例外を握りつぶさない。想定内は §4 の形に、想定外はログして500
- ログに**個人情報・パスワード・トークン・業務データを出さない**

## 8.5 死ぬ列を作らない

台帳の `ステータス` は13件すべて「進行中」、`次回アクション` はほぼ「次回MTG」だった。
アポイント管理表の `進捗` `契約状況` は**一度も使われていない**。

**既定値のまま置いても困らない列は、必ず死ぬ。**

- 選択肢に**既定値を置かない**（未選択は未選択として出す）
- 埋まっていないことを**「要確認」として一覧に出す**（土台 §4.1）
- 埋めないと次に進めない場面を作る。**画面から促す**

## 9. テスト

- 機能ごとに1ファイル。**「動くか」ではなく「壊れたら困ることが守られているか」**
- 実データで踏んだ不具合は**必ず回帰テストにする**
- マージ前に全部通っていること

## 10. バッチ

- **`--dry-run` を既定にし、`--apply` で初めて書き込む。**件数と例を出す
- 人が入れた値を**上書きしない**（空いているところだけ埋める）
- メモ欄は**追記**する

## 11. 外部API

- **User-Agent を名乗る。**名乗らないと言語標準のUAになり、WAFに弾かれることがある
- 流量制限は**クライアント層で守る。**呼ぶ側に任せない
- ページングは**打ち切りの上限**を持つ
- 外部から叩かれるAPIは**CSRFの対象外にする**（`app/__init__.py` にコメントあり）。
  外し忘れると外部連携が黙って止まる

## 11.5 時刻

- **保存はUTC（タイムゾーン無し）、画面はJST。**`app/timeutil.py` を通す
- `datetime.utcnow()` を書かない（Python 3.12で非推奨・将来削除）。`utcnow()` を使う
- テンプレートで `strftime` を直接呼ばない。**`{{ 値|jst }}`** を使う
- 未設定の日時は「—」を出す。空欄にしない

## 12. 画面

- 数字は右揃え・桁区切り
- 合計だけでなく**内訳を出す**
- 空欄に「—」とだけ出さず、**なぜ出ないのかを書く**
- 押した瞬間に保存されるのか、ボタンが要るのかを**明示する**

## 13. 禁止

- 共有ファイル・ルート規約・API応答形を独断で変える
- 生SQL・DBの手編集
- 履歴を残さない更新／ホワイトリスト外の項目の更新
- 秘密のハードコード・ログ出力
- 汚れたデータ（未採番・未紐付け・重複）の無断削除
