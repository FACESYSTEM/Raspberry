## 使い始める

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # SECRET_KEY と CREDENTIAL_KEY を作って入れる
.venv/bin/python scripts/init_db.py --email あなた@example.com --name 名前
.venv/bin/python -m pytest -q # 182 passed になること
PORT=8010 ./deploy/start.sh
```

鍵の作り方：

```bash
python3 -c "import secrets;print(secrets.token_urlsafe(48))"
```

`CREDENTIAL_KEY` は**失うと保管したパスワードを復号できません。**
環境ごとに別の鍵を作り、控えを持たせてください。

## 最初にやること

### 1　業務の言葉を決める　**（済）**

`CONVENTIONS.md` §7 の用語辞書を、**業務の言葉で埋めるところから**始めます。
ここが曖昧なまま作ると、画面ごとに呼び方がぶれます。

### 2　役割を決める　**（済：master / owner / staff の3つ。outside は外した）**

`app/security.py` の `ROLES` です。初期値は4つ。

```
master   開発側。作りかけの機能も見える
owner    先方の管理者
staff    担当者
outside  社外の方。自分に紐づくものだけ見える
```

**使われない役割を置かないでください。**
実案件では「責任者」「閲覧のみ」を外しました。該当者がおらず、
選ぶときに迷わせるだけだったためです。

### 3　見本のドメインを置き換える　**（済：ゲスト・キャスト・ボトル・来店・担当）**

`Partner`（取引先）と `app/main/` は**作法を見せるための見本**です。
業務が決まったら作り直すか、消してください。

見本が示していること：

* 一意制約を付けない（同名・表記ゆれが実在する）
* 消さずに下げる（`archived_at`）
* 汚れているものを消さず「要確認」に出す（`issues`）
* インライン編集は、押した瞬間に保存して履歴を残す

## 持ち込んだ「作法」

実案件で踏んだ失敗への対策です。**消さないでください。**

### 認証・秘密

* 初期パスワードを人が決めない（招待リンク。合言葉は使い捨て）
* パスワードはハッシュのみ。**開発側からも読み出せない**
* 鍵が無ければ保存を拒む（平文で置かない）
* 一覧に平文を出さない。押した1件だけ返し、見たことを残す
* **メールが出ない環境で「送りました」と言わない。**
  届かないものを待たせない（`/forgot` が設定の有無で出し分ける）
* **「使えません」で終わらせない。**
  使用済みの招待リンクから、ログイン画面へ案内する

### データ

* 未採番・重複を許す（一意制約を付けない、NULL可）
* 汚れは消さず「要確認」に出す
* 消さずに下げる（`archived_at` / `ended_at`）
* 履歴を伴わない更新を書かない。秘密の値は履歴に入れない
* **「無い」と「分からない」を区別する。**
  分からないものを黙って既定値に寄せると、合計が狂っていることに誰も気づけない
* **列で持てるものは、導いて出す。**
  人数から規模を出す。契約から継続／過去を出す。
  両方持つと、片方だけ古くなる

### 見せ方

* 公開していない機能は **404**（403にしない。あることを知らせない）
* **自分より上の役割を見せない。**
  「全部×」の行を残すと、そこに何かあると分かってしまう
* 開発側の利用者を、先方の一覧に出さない。**URLを直に叩いても触れない**
* **開けない人にリンクを出さない。**押して403が一番こたえる
* できることの一覧表は、**判定関数から作る**（手書きだと必ずずれる）

### 運用

* 点検は問題があるときだけ知らせる。4xxもNGにする。UAを名乗る
* **列を足す道具を持つ**（`scripts/add_columns.py`）。
  `upgrade_db.py` は表しか作れない
* 外部APIをCSRF対象外にする箇所を `app/__init__.py` にコメントで残してある

## 修正モード（`packages/fixmode/`）

**画面を見ている人が、その場で「ここを直して」と言える**仕組みです。

```
使い手が、直したい場所を四角く囲んでひとことを書く   → オレンジの枠
作り手が「直しました」と伝える                  → みどりの枠
使い手が押して「直っています」で閉じる            → 枠が消える
```

**直した本人は閉じられません。**
同じ人が両方できると「直したつもりが直っていない」が通ります。

組み込み方は `packages/fixmode/README.md` にあります。
**この土台から切り離して、他のシステムにも持っていけます。**

## 先方の環境に置く

`deploy/README.md` に手順があります。要点：

* アプリは `127.0.0.1` でしか待ち受けない。外からは Caddy 経由だけ
* 証明書は Caddy が自動で取る（80と443が開いていること）
* **古いホスト名も残す。**既に渡したリンクを切らさないため
* 夜間点検とバックアップを cron に入れる
